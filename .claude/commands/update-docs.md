# Update Docs

コードを読んでゲーム仕様書（Spec/\*.md）を2段階（分析→書き出し）の並列チームで更新する。

## 手順

### 1. 変更差分の把握

`git log --oneline --since=<前回更新日>` で前回の仕様書更新以降のコミットを確認する。
前回更新日は `Spec/README.md` の更新履歴から取得する。

### 2. Phase 1: コード分析（doc-analyzer × 3チーム並列）

以下の3チームに分けて **doc-analyzer** エージェントをバックグラウンドで **同時に** 起動する:

| チーム       | 対象ファイル                                           | 確認するコード                                                                              |
| ------------ | ------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| Core Game    | game-overview 関連, game-mechanics 関連の仕様書        | `src/Lib/Core/*`, `src/Lib/Data/*`, `src/Lib/Types/Battle.ts`, `src/Lib/Types/Command.ts`   |
| Data & State | data-structures, state-management 関連の仕様書         | `src/Lib/Types/*`, `src/Lib/State/*`, `src/Lib/Storage/*`                                   |
| UI           | ui-components 関連の仕様書                             | `src/Components/*`, `src/Hooks/*`                                                           |

各チームのプロンプトには以下を含める:

- 対象の仕様書ファイル一覧（Spec/配下のパス）
- 関連するコミット一覧（手順1で取得したもの）
- 確認すべきコードのパス
- 更新ルール（手順5参照）

doc-analyzer は差分リスト（追加/修正/削除すべき内容）を返す。ファイルの変更は行わない。

### 3. Phase 2: 仕様書書き出し（doc-writer × 3チーム並列）

Phase 1 の全チーム完了後、各チームの分析結果を対応する **doc-writer** エージェントに渡してバックグラウンドで **同時に** 起動する。

各 doc-writer のプロンプトには以下を含める:

- doc-analyzer が生成した差分リスト（そのまま全文）
- 対象の仕様書ファイル一覧
- 更新ルール（手順5参照）

doc-writer は差分リストに従って仕様書を実際に更新する。

### 4. 結果の統合

全 doc-writer チーム完了後:

- `Spec/README.md` の更新履歴に、全チームの変更内容を1つの日付エントリとしてまとめて追記する
- 更新サマリーをユーザーに表示する

### 5. 更新ルール（各チーム共通）

- **コードが正（Source of Truth）**: 仕様書とコードにズレがあればコードに合わせる
- パラメータ調整対象の値（ダメージ倍率、HP回復量など）は概要表現に留める
- ゲーム構造に関わる固定値（属性の種類数、コマンド種別数など）は記載する
- 各ファイルは800行以下に収める
- 新機能があればセクションを追加、削除された機能は仕様書からも削除
- **コードの変更は行わない**（仕様書のみ更新）
