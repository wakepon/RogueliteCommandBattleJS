# Weekly Summary Skill

過去一週間のgitコミット履歴を分析し、主要な変更点をチーム共有用のMarkdownにまとめる。

## 使用タイミング

- `/weekly-summary` で呼び出された時
- 週次の振り返りや共有をしたい時

## 引数（オプション）

- `--author=<name>`: 特定の著者でフィルタ（例: `--author=sotak`）。省略時は全著者
- `--days=<N>`: 過去N日分を対象（デフォルト: 7）
- `--since=<date>`: 開始日を直接指定（例: `--since=2026-02-24`）

## 実行手順

### Step 1: コミット履歴の取得

```bash
# 日付付きコミット一覧（マージコミット除外）
git log --since="<対象開始日>" --author="<著者>" --format="%h %ad %s" --date=short --no-merges
```

著者指定がない場合は `--author` オプションを省略する。

### Step 2: コミットの分類・グループ化

取得したコミット群を以下の観点で分析・分類する:

1. **関連するコミットをグループ化**: 同一機能・同一目的のコミットをまとめる
   - 例: レリック関連のfeat/fix/docsは1つの項目にまとめる
2. **重要度で選別**: 細かなfix・choreより、大きなfeat・新システム・リファクタを優先
3. **3〜20項目に収める**: 多すぎず少なすぎない粒度にする

### Step 3: カテゴリ分け

項目を以下のようなカテゴリに分類する（該当するもののみ使用）:

- **新システム追加**: 完全に新しい機能やシステム
- **大規模リファクタリング**: アーキテクチャ変更、用語統一、方式変更
- **UI・UX改善**: 表示変更、ツールチップ、レイアウト
- **バランス調整**: ゲームパラメータの変更
- **ゲームルール変更**: 仕様レベルの変更
- **バグ修正**: 重要なバグの修正
- **開発環境改善**: ツール・ワークフロー・CI関連

カテゴリは変更内容に応じて自由に調整してよい。

### Step 4: Markdownの作成

以下の形式で `Spec/Summaries/weekly-summary-YYYY-MMDD.md` に書き出す。

```markdown
# 週次変更サマリー（MM/DD〜MM/DD）

## カテゴリ名

### 1. 項目タイトル

- 変更の概要（何が変わったか）
- 具体的な内容（必要に応じて箇条書き）

### 2. 項目タイトル

- ...

## 別のカテゴリ名

### 3. ...
```

### Step 5: ユーザーへの報告

書き出したファイルパスと、主要な変更のハイライト（3〜5行程度）を簡潔に伝える。

## ガイドライン

- **人間が読むことを前提に書く**: 技術的なコミットメッセージをそのまま転記せず、何が変わったかを平易に説明する
- **コミットハッシュは不要**: 人間向けなのでハッシュは省略する
- **小さなfix群はまとめる**: 同カテゴリの小さな修正は1項目にまとめてよい（例: 「武器バランス調整（多数）」）
- **docsコミットは基本省略**: 仕様書同期やcodemap更新は省略。ただし新しい設計ドキュメントは含めてよい
- **開発環境系は控えめに**: チーム共有向けなので、Claude Code固有の設定変更は大きなものだけ記載

## 注意事項

- このスキルは分析とファイル書き出しのみ行う。コミットやプッシュはしない
- 既存の同名ファイルがある場合は上書きせず、ユーザーに確認する
