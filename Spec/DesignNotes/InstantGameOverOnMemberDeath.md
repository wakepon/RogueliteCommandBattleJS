# メンバー1人死亡で即ゲームオーバー化 + 祈り強化

## ステータス: 保留（条件付き・代替案を強く推奨）

ユーザー意図（クリア見込みのない状態がダラダラ続くのを断つ）は妥当だが、「1人死亡で即敗北」は既存メカニクスの破壊が大きく、不公平感も増える。Darkest Dungeon 風の **「気絶（Death's Door）」状態** を経由する代替案が、緊迫感とリソース管理の伸長というメリットを得つつデメリットを抑えられる。祈り魔法は **+30〜35%** に留めるのが無難。

---

## 現状仕様（調査結果ベース）

### 戦闘不能 / 敗北の現状フロー

| 項目 | 現状 |
|---|---|
| HP=0 メンバー | 行動順から除外、コマンドスロット非生成、被弾対象から除外、毒スキップ |
| 敗北判定 | `checkBattleResult` (`BattleEngine.ts:32`) が `party.every(m => m.hp <= 0)` のとき `'defeat'` |
| 戦闘終了時 | 勝利時のみ `hp <= 0 ? 1 : hp` で復活（`GameReducer.ts:163-168`）。敗北時は復活なし |
| 身代わりの人形レリック | 致死ダメージで HP1 復活（`BattleActionProcessor.ts:129-163`、`applyDeathProtection`） |
| 死体配置戦術 | 先頭が死体なら前衛なし扱い（`getFrontMemberId` null）→ 生存者全員が後衛重みで按分 |

### 敵火力と後衛HPの関係

- 後衛HP: 魔法使い 30, 僧侶 40
- 単体最大火力: オーク40, アサシン35, スリープタイガー20×2(40), ドラゴン55
- AoE: ドラゴン Phase1 18, Phase2 25
- **後衛は1〜2発で死ぬ**設計。被弾率分散と祈り集中で耐える前提

### 祈り魔法の現状

- `prayer` weapon、targetType: allySingle、無限使用、`{ type: 'targetRateUp', value: 25, duration: 1 }`
- 計算式（`TargetingSystem.ts:30-104`）: 対象に絶対値+25%、非対象は重み比で按分減少
- 重複時は合算 → 合計>1.0 で正規化

## 仕様変更案A: 1人死亡で即ゲームオーバー

### 影響範囲

| 既存機構 | 影響 |
|---|---|
| `BattleEngine.checkBattleResult` | 判定式を `party.some(m => m.hp <= 0)` に変更 |
| `BattleActionProcessor.applyDeathProtection`（身代わり） | 呼び出しタイミングを「死亡判定の前」に厳密に保つ必要。AoEで複数致死時の処理順が複雑化 |
| 死体配置戦術（PositionUtils） | 即敗北なので戦術として成立しなくなる。`getFrontMemberId` の死体先頭ルールも無意味化 |
| 戦闘終了時 HP1 復活 | 敗北直前の最後の生存者を救うロジック。即敗北仕様では全滅扱いにせず、復活させる対象が「敗因の1人だけ」になり違和感 |
| ターン中の死亡判定 | 敵 1action ごと/毒ダメージごとに `checkBattleResult` を呼んで即遷移する必要 |
| 祈り戦術 | 「前衛に祈り→後衛保護」が逆に「祈り対象が死ぬ＝即敗北」のリスク要因に変わる |

### 想定されるメリット

1. クリア見込みなしのダラダラ負けが解消
2. 緊迫感が大幅に増す（1人の死が即座のリセット）
3. 祈り・回復・被弾率管理の重要性が跳ね上がる
4. 「リソース管理 + ランダム操作」というゲームの特徴がより尖る

### 想定されるデメリット・懸念

1. **不公平感の増大**: 後衛を狙う乱数が連続したり、AoE後の単体追撃で確定死するケースが増える。プレイヤー責任ではない敗北が増えると「やってられない」感情になる
2. **大技インテント時の駆け引き消滅**: 「誰かを犠牲にして火力をキープ」という現状の渋い選択肢がゲームから消える。ターン制バトルの戦略幅が縮む
3. **被弾率分散の意義激減**: 死体を idx0 に置いて50/50で耐える戦術は「1人でも死ねば敗北」では成立しない。せっかく実装した前後衛ダイナミクスが死ぬ
4. **身代わりの人形が必須レリック化**: 取れるか取れないかで難易度が極端に変わり、ピック運に支配される
5. **オークの渾身40ダメージ → 戦士HP60に当たって生存だが、後衛HP30に当たって即死亡 → 即敗北**のパターンが増える。後衛HPバランスを大幅引き上げないと初心者には酷
6. **ボス戦（ドラゴン HP270, AoE25）**: 12ターンの間1人も死なせない、はかなりの上級者プレイ要求

## 仕様変更案B: 祈り魔法 +25% → +50%

### 試算（前衛1+後衛2、3人生存）

| パターン | 前衛 | 後衛A | 後衛B |
|---|---|---|---|
| 通常（祈りなし） | 50% | 25% | 25% |
| 前衛に祈り+25% | 75% | 12.5% | 12.5% |
| 前衛に祈り+50% | **100%** | 0% | 0% |

### 懸念

- **正規化の影響**: 複数人に+50%を重ね掛けすると合計が1を超え、現行コード（`TargetingSystem.ts:99-103`）が全体を正規化して効果が弱まる。「全員+50%」と「1人だけ+50%」の差がブレやすい
- **強すぎ判定**: 前衛被弾率100%は「祈り＝完全な肉壁」を作る支配戦略になりやすい。+25%は分散戦術の調整として丁度よく、+50%は構造を変える
- **全体ヒール（癒しの風 HP+15）との相互作用**: 全員後衛被弾0%にできれば、生存者2人体制でも後衛が無傷で凌げる場面が増える

### 案Aと組み合わせる場合の意味

案A（即ゲームオーバー）の救済として「祈り+50%で前衛固定狙撃→後衛0%」を成立させたい意図は理解できる。ただし:
- AoE攻撃には祈りが効かない（AoEは全員ヒット）
- 祈りduration=1なので、毎ターン僧侶が前衛に祈り続けるしか選択肢がなくなる → 戦術の単調化
- 僧侶のMP（初期15）は無限使用「祈り」自体は0コストだが、攻撃と回復のターン余裕がなくなる

## 代替案: Darkest Dungeon 風「気絶 (Death's Door)」状態

### 機構の概要

HP=0 になったメンバーは即死せず **「気絶」状態** に入る。

- 気絶中: コマンド入力不可、行動順スキップ
- 気絶中に**さらに攻撃を受けると一定確率（例: 67%）で完全死亡**、または**確定で完全死亡**
- 完全死亡したメンバーがいる戦闘は終了時にも蘇生不可（その run で永久ロスト）→ **その瞬間ゲームオーバーまたは run 続行を選択**
- 気絶状態は HP1 以上の回復で解除（heal/healing_wind/HP potion）
- 戦闘終了まで完全死亡せずに済めば、勝利時 HP1 で復活（既存仕様維持）

### 何が変わるか

- **緊迫感は維持**: 1人気絶した瞬間「次の被弾で死ぬ」プレッシャーが走る
- **救済可能**: 直後のターンに heal すれば助かる → リソース管理ゲームとしての駆け引きが残る
- **ダラダラ負け解消**: 気絶→死亡の流れは1〜2ターンで決着する。死亡判定のタイミングをコントロール可
- **大技インテント時の駆け引き温存**: 「誰かを犠牲に〜」が「気絶を許容して反撃 → 次のターンで全力ヒール」というリスクヘッジ可能
- **乱数の不公平感を吸収**: 後衛連続被弾でも、1発目は気絶で済む → 直後のターンで救済できれば取り返せる
- **死体配置戦術の維持**: 気絶メンバーを idx0 に置けば「先頭が気絶=後衛50/50」の現行ロジックがそのまま生きる

### 機能整理

| 状態 | HP | 行動 | 被弾対象 | 解除方法 |
|---|---|---|---|---|
| 通常 | >0 | 行動可 | 含む | - |
| 気絶 | =0 | 不可 | 含まない（または弱い被弾率） | HP回復 |
| 完全死亡 | =-1（特殊値） | 不可 | 含まない | run中復活不可、戦闘終了時にもHP1にならない |

### コスト

- `ExplorerState` に `downed: boolean` フラグ追加（または HP=-1 で完全死亡を表現）
- `BattleEngine.checkBattleResult` を「全員 downed または完全死亡 で defeat」「1人でも完全死亡で defeat」に変更
- `applyDeathProtection`（身代わりの人形）は気絶→完全死亡の遷移時に作動するよう調整
- 既存の `getFrontMemberId` の「先頭が hp<=0 なら前衛なし」ロジックはそのまま活かせる

## 別の代替案

### A1. 「2人死亡で即ゲームオーバー」（軽量版）

「1人」を「2人」に緩めるだけ。

- 既存の死体配置戦術が成立（1人までは盾化可）
- 緊迫感はそこそこ。3人→2人になる瞬間に終了するので「最後の1人で粘る」フェーズはない
- 実装はほぼ自明（`some` ではなく `count >= 2`）
- ユーザー意図の「クリア見込みなし状態がダラダラ続く」は完全には解消しないが、3人→2人→1人→0人の中盤2フェーズが圧縮される

### A2. 「投了/敗北宣言」UI

戦闘中にプレイヤーが任意で「敗北宣言」できるボタンを追加。

- ゲームバランスは一切いじらず、UIのみ
- 「もう無理」と思ったら自分で終わらせられる → ダラダラ感の解消
- 緊迫感は変わらず、駆け引きも温存
- ユーザー意図のうち「緊迫感UP」「祈り重要性UP」は満たせない

### A3. 「ペナルティ蓄積による run 終了」

メンバー死亡が累積で run 全体に呪いが付き、ある閾値で強制 run 終了。

- バトル単位での即ゲームオーバーではなく、run 単位の蓄積管理
- 設計が複雑、初心者には読みにくい

## 祈り強化の独立判断

案Aとは独立に「祈り魔法を強化すべきか」を考えると:

| 値 | 評価 |
|---|---|
| +25%（現状） | 前衛75% / 後衛12.5%。バランス取れている |
| +30〜35% | 前衛85〜95%。やや強化されるが正規化に達しない |
| +50% | 前衛100%、後衛0%。強すぎ・支配戦略化リスク |
| +50%＆毎ターン強制 | 上記 + 単調化 |

**推奨: +30%** か **+35%**。前衛被弾率を 90% 前後に押し上げる程度に留め、複数人重ね掛けでも正規化に達しないバランスにする。AoEには効かないので「全体攻撃 vs 単体攻撃」の使い分けが意味を持ち続ける。

## 判断

### 結論

- **案A（1人死亡で即ゲームオーバー）はそのままでは保留**。既存メカニクス（死体配置・身代わりの人形・大技駆け引き）への破壊が大きく、不公平感とのトレードオフが釣り合わない
- **代わりに「気絶（Death's Door）」案を強く推奨**。ユーザー意図のメリット（緊迫感、リソース管理重要性、ダラダラ負け解消）をほぼ満たしつつ、デメリット（不公平感、駆け引き喪失）を吸収できる
- **祈り魔法は +30〜35% 程度に留める**。+50%は支配戦略化のリスク

### 推奨実装パス

1. まず「気絶」状態を追加（`ExplorerState.downed` フラグ + HP回復で解除）
2. 気絶中に再被弾で完全死亡 → 即敗北
3. 祈り魔法を +30% に微調整
4. プレイテストし、緊迫感とフェアネスのバランスを観察
5. 上記でも「ダラダラ負け」が残るなら、「投了ボタン（A2）」を追加で導入

### 採用しない場合の最低限の代替

ユーザーがどうしても「1人死亡＝即敗北」を採用したい場合:

- 後衛HPを底上げ（mage 30→45, cleric 40→55 等）
- 身代わりの人形を初期所持 or ショップ確定枠に
- 祈り効果を前衛狙撃用として +35% 程度に強化
- 大技インテント表示を更に明確化（ターゲットを事前確定表示）

## 検証観点（実装した場合）

| シナリオ | 期待挙動 |
|---|---|
| 通常戦闘でメンバー1人がHP0に | 「気絶」表示、行動不可、被弾対象から外れる |
| 気絶中にAoE被弾 | 完全死亡 → 即ゲームオーバー |
| 気絶中の次ターンに heal | 気絶解除、HP回復値分復帰 |
| 気絶中に身代わりの人形が発動 | 気絶状態のまま HP1 復活、レリック消費 |

| ターゲティング: 気絶メンバーは前衛から除外 | `getFrontMemberId` で hp<=0 をスキップ（既存通り） |
| 祈り+30%適用時の前衛被弾率 | 前衛 80%、後衛 各 10% |
