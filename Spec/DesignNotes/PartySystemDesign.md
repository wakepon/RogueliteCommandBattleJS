# パーティー制バトルシステム設計

## ステータス: 導入推奨

3人パーティー制を導入し、コマンド式RPGの手触りを維持しつつ、毎ターンの意思決定の質と量を根本的に改善する。

---

## 背景と課題

### このゲームが提供したいもの

1. **いにしえのRPGのようなコマンド式バトルを今風のローグライクにして提供する**
2. **ダンジョンを通してのリソースマネジメントという新しい遊びを提供する**

### 現状の問題

- 1キャラ×1コマンド選択では、多くの場面で最適解が1つに収束する
- StSでいえば「手札から1枚しか出せない」ような状態で、プレイヤーに意味のある選択をさせることが構造的に難しい
- FiveCoreProblemAnalysis.mdで指摘した5つの問題（火力偏重、シナジー不足、武器温存、リソース消費抑制、判断前ランダム不在）は、この「選択肢の不足」から派生している
- コンテンツの追加（武器・魔法の種類増）だけでは根本解決しない

### 検討した代替案

**案A: パーティー制（3人）**

| 観点 | 評価 |
|---|---|
| コマンドRPG感 | ◎ まさにいにしえのRPGの体験 |
| 選択の質 | ◎ 1ターンに3回の判断（誰が×何を×誰に） |
| リソース管理 | ◎ 3人分のHP/MP/武器耐久を管理。配分判断が生まれる |

**案B: インプットランダム（Spell Rogueのようなダイス導入）**

| 観点 | 評価 |
|---|---|
| コマンドRPG感 | △〜× ダイス主体になりRPGの手触りが薄れる |
| 選択の質 | ○ 出目に応じた分岐は生まれる |
| リソース管理 | × ダイス運でリソース消費が変わると計画的な管理が成立しにくい |

**判断: パーティー制を採用**

理由: パーティー制が2つのコア目標（コマンド式バトル＋リソースマネジメント）を**両方とも**強化する。インプットランダムは選択の面白さを増すがコマンドRPG感を犠牲にし、リソース管理との相性も悪い。パーティー制を導入した上で選択の質がまだ足りなければ、その時点でインプットランダムの追加を検討する。

### 「既存の嫌な部分の改善」フレーミング

ヒットする商品は「既存の嫌な部分を改善したもの」であるという考えに基づき、このゲームの位置付けを整理する。

1. **RPGの「たたかう連打」が退屈** → ターン制限＋リソース制約で毎ターン全力。通常攻撃（パンチ）だけではターン制限内に倒せない設計にすることで、「たたかう連打」を構造的に不可能にする
2. **RPGの「1人ずつコマンド入力が面倒」** → ドラッグ&ドロップの同時選択UIで、キャンセル連打の面倒さを解消しつつパーティー戦略を楽しめる
3. **デッキビルダーの「冒険感のなさ」** → カードゲームではなく、パーティー＋装備＋ダンジョン探索という「RPGの冒険者ファンタジー」で戦略的深さを実現

## パーティー構成

### 初期ステータス

```
         HP   MP   STR  INT  武器枠         魔法枠
戦士:    60   5    7    3    4(+パンチ)      0
魔法使い: 30   25   3    7    0(+魔力弾)     4
僧侶:   40   15   4    5    1(+祈り)       3
```

**AGIを廃止した理由:** 行動順はUI上のドラッグ&ドロップでプレイヤーが自由に決定する設計にしたため、AGIパラメータは不要。AGIで自動決定すると行動順UIの意味がなくなる。

**武器枠/魔法枠を分離した理由:** 統合も検討したが、枠が決まっているほうが(1)選択時の脳負荷が低い、(2)キャラごとのコントラストが明確になる。

### 初期装備

```
戦士:     錆びた剣(耐久3) + パンチ。残り3枠空き
魔法使い:  ファイア(MP3) + 魔力弾。残り3枠空き
僧侶:    ヒール + 祈り。武器枠1空き、魔法枠2空き
```

**初期バランスの意図:** ダメージの振れ幅により、戦士や魔法使いの1回の攻撃でスライムを倒せるときもあれば倒せないときもある状態にする。Stage 1でスライム2体が出た場合に「確実に1体倒すか、2体同時撃破に賭けるか」という選択が初戦から生まれる。スライムはHPが低く弱いため、その代わりに攻撃力を上げてリソース消費の緊張感を維持する（具体値はプレイテストで調整）。

### レベルアップ成長

```
         HP   MP   STR  INT
戦士:    +7   +1   +2   +0
魔法使い: +3   +4   +0   +2
僧侶:   +5   +3   +1   +1
```

非対称な成長にする理由: 「戦士はレベルが上がるとHPがガッと増える」「魔法使いはMP回復の恩恵が大きい」と、レベルアップの価値がキャラごとに異なるため、「誰をレベルアップさせるか」の判断に意味が生まれる。

### レベルアップ条件（キャラ個別）

```
基本ルール:
  - 敵を討伐 → 全員の討伐数+1
  - 止めを刺したキャラ → 追加で+1（合計+2）
  - 必要討伐数はキャラごとに個別管理
  - レベルアップ効果: そのキャラのHP/MPを全回復
```

**全員同時レベルアップにしなかった理由:** 全員同時だと「誰に止めを刺させるか」の戦略が生まれず単純すぎる。フィニッシュボーナスにより:
- 戦士は攻撃機会が多い → レベルが上がりやすい
- 僧侶は回復/バフ役で止めを刺しにくい → レベルが遅れがち
- だが僧侶には武器枠1があるので止めを狙うことも可能
- 「誰をレベルアップさせたいか」でターゲット選択が変わり、リソース管理と直結する

### 無限行動（キャラ別）

```
戦士:    パンチ  → STR依存, Power1, ±2, 敵を対象
魔法使い: 魔力弾  → INT依存, Power1, ±2, 敵を対象
僧侶:   祈り    → 味方を対象 → 対象の被ターゲット率UP（次の敵フェーズ）
```

**全員統一の「パンチ」にしなかった理由:** キャラ別にすることで個性が出る。特に僧侶の「祈り」は確率コントロール（＝確実性を買うゲーム性）を無限行動として常に選択肢に置くことで、このゲームのコアメカニクスをプレイヤーが自然に学べる。

### 死亡と全滅

```
HP0 → 戦闘不能（そのバトル中は行動不可）
バトル終了時 → HP1で復活
全員HP0 → 全滅（ラン終了）
```

**HP1復活にした理由:** 復活手段が別途必要になると複雑度が上がる。HP1で自動復活なら「次のバトルまでにヒールが必要」というリソース管理の判断に変換される。

**戦闘不能キャラのバトル中の扱い:**
- 戦闘不能キャラの欄はグレーアウト（コマンドセット不可）
- 行動順スロットは生存キャラ分のみ表示（例: 通常3スロット → 1人死亡で2スロット）
- コマンドセット済みでもHP0になった時点でその行動はスキップ（レリックや武器/魔法の副作用で発生しうる特殊ケース）

## バトルシステム

### ターン進行

```
1. コマンド選択フェーズ（プレイヤー）
   - 3人のコマンドを同時にセット（ドラッグ&ドロップ）
   - 行動順スロットを調整
   - ポーションはフリーアクションで即使用可
   - 「実行」ボタンで確定

2. パーティー行動フェーズ
   - 行動順スロットの順に3人が行動

3. 敵行動フェーズ
   - 全敵が行動（ターゲットは確率で決定）
```

**パーティー→敵の順序にした理由:** 行動順スロットに敵も交じるとUIが複雑になり、ユーザーが理解しがたいものになる。パーティー全員→敵全員のシンプルな2フェーズ制なら直感的。

### 行動順スロット

- 画面上部に3つのスロットが並び、キャラの顔アイコンが入る
- ドラッグ&ドロップでコマンドをセットすると、セットした順にスロットに入る
- スロット間のドラッグ&ドロップで順番を入れ替え可能

**行動順が戦術になる例:**
- 僧侶の「精密」→ 戦士の攻撃（バフ乗せ、順番が逆だとバフが無駄）
- 魔法使いのデバフ → 戦士の攻撃（弱点突き）
- 戦士の攻撃で倒す → 僧侶のヒールが不要に（別の行動に変更可能）

### 敵行動の事前予告

ターン開始時に敵の次の行動を表示する。

**導入理由:** 1人パーティーでは敵行動予告があっても「耐える or 殴る」の2択しかない。3人パーティーなら「戦士が挑発して受け止める」「僧侶が先にヒール」「魔法使いが先に倒す」等、対応の組み合わせが豊富になり予告情報の価値が飛躍的に上がる。

### 前衛/後衛とターゲティング

```
配置:
  前衛: 戦士
  後衛: 魔法使い、僧侶

基本被ターゲット率:
  前衛は後衛の2倍の確率で狙われる
  → 前衛50%、後衛A 25%、後衛B 25%
```

**前衛/後衛の2段階にした理由:** 前方ほど被ターゲット率が高いグラデーション方式だと、戦闘ごとに細かく並び替えしたくなりテンポが悪化する。前衛/後衛のシンプルな2段階なら、将来パーティー人数が変わっても「前衛は後衛の2倍」で統一できる。

**確実性を買う手段:**
```
・祈り（僧侶の無限行動）→ 対象の被ターゲット率+25%、残りを按分減少
  例: 戦士に祈り → 前衛75%、後衛各12.5%
・挑発系（戦士の特殊武器/魔法）→ 次ターン敵の攻撃を自分に集中（100%）
・隠密系（僧侶の魔法）→ 味方1人の被ターゲット率を0にする
```

被ターゲット率はバトルUI上にプレビュー表示する。

### アウトプットランダムの設計方針

このゲームはアウトプットランダム（行動選択後に結果が確率で決まる）を採用する。

**クリティカルを廃止した理由:** ダメージブレ（±variance）で十分な不確実性がある。クリティカルを加えると(1)確率設定が難しい（3%だとラン中未発生、30%だと運ゲー）、(2)キルラインバーの信頼性が下がる（表示範囲外のダメージが出る）、(3)複雑度の上昇の割に得られる効果が薄い。

**「確実性を買う」をコアメカニクスにする:**
- ダメージブレの確実性 → MPで買う（精密の魔法）
- ターゲティングの確実性 → 行動で買う（祈り/挑発/隠密）
- キルラインバーで「倒せるか」が可視化され、確実にするかリスクを取るかの判断が常にある
- 「確実性を買うゲームだ」と早期に気づいてもらうため、僧侶の初期魔法に「精密」を配置

### 精密（僧侶の初期魔法）

```
対象: 味方1人
効果: 次の1回の攻撃のブレ幅→0（最大ダメージ固定）
MP消費: 3
行動消費: あり（僧侶の行動を使う）
持続: 次の1回の攻撃のみ
```

**初期魔法にした理由:** Stage 1で自然に「精密を使ったらキルラインバーの確定ダメージが伸びた」体験が起き、プレイヤーが「確実性をMPで買う」コアメカニクスを直感的に理解できる。

## バトルUI（ドラッグ&ドロップ方式）

### UI方式の選定経緯

パーティー制にした場合のコマンド入力UIを3案検討した:

| 方式 | コマンドRPG感 | 操作性 | 戦略性 |
|------|------|------|------|
| A: 順番選択＋キャンセル（従来RPG） | ◎ | × 僧侶まで行った後に戦士を変えたい時のキャンセル連打がダルい | ○ |
| B: 順番選択＋即実行（巻き戻し不可） | ○ | ○ | × 全体を見て計画できない |
| C: 同時選択＋ドラッグ&ドロップ | ○ | ◎ | ◎ |

**方式Cを採用した理由:**
- PC（マウス操作）がメインプラットフォーム → ドラッグ&ドロップが直感的
- 「武器を選んで対象にドロップ」が「命令する」感覚でコマンドRPG感を維持
- 順序制約なし → どのキャラからでも変更可能でキャンセルの概念が不要
- 本質的にはドラクエの「めいれいさせろ」の快適版。順番入力が面倒だっただけで、一覧で同時設定できれば同じ体験

### 画面構成

```
┌──────────────────────────────────────────────┐
│  [敵1: ゴブリン HP12]      [敵2: オーク HP30] │
│   次: 斬りつける(5)         次: 力溜め        │  ← 敵行動予告
│   [キルラインバー]          [キルラインバー]    │  ← 常時表示
├──────────────────────────────────────────────┤
│  行動順: [戦士①] → [僧侶②] → [魔法使い③]    │  ← ドラッグで入れ替え
├──────────┬──────────┬──────────┬────────────┤
│  戦士     │  魔法使い │  僧侶    │ ポーション  │
│ HP40/60  │ HP20/30  │ HP35/40  │            │
│ 被弾:50% │ 被弾:25% │ 被弾:25% │ HPポーション│
│ →鉄の剣  │ →ファイア │ →精密   │ MPポーション│
│  →敵2   │  →敵2   │  →戦士  │────────────│
│          │          │          │ レリック    │
│ ⚔大斧   │ ❄アイス   │ ✚ヒール  │ 天使の天秤  │
│ ⚔投げナイフ│ 🔥ファイアS│ 💪バフ  │            │
│ 👊パンチ  │ 👊魔力弾  │ ⚔短剣   │            │
│          │          │ 🙏祈り   │            │
├──────────┴──────────┴──────────┴────────────┤
│                  [ 実行 ]                     │
└───────────────────────────────────────────────┘
```

### 操作フロー

1. キャラの武器/魔法を**敵 or 味方にドラッグ&ドロップ** → コマンドセット
2. セット済みコマンドはキャラ欄に「→対象」として常時表示
3. 行動順スロットにキャラ顔が入る（セット順。ドラッグで入れ替え可）
4. **どのキャラからでも自由にセット/変更可能**（順序制約なし、上書きで変更）
5. ポーション → キャラにドロップで**即使用**（フリーアクション、行動消費なし）
6. 3人分セットしたら「実行」

**共有枠のレイアウト理由:** ポーションとレリックは僧侶の隣に配置し、実行ボタンとは区分け。実行ボタンの手前にポーションがあると毎回使用を促される感じで煩わしい。ポーションとレリックは意味的に異なるので枠内で区切る。実行ボタンはキャラ枠・共有枠とは独立した最下段の行に配置し、「全体の確定操作」であることを明示する。

### キルラインバー（常時表示）

敵のHPバーに「このターンの攻撃結果」を割合で重ねて表示:

```
  [■■■■■■■□□□□□░░░░░░░░]
   ←確定ダメ→←ブレ幅→←残HP→

  ■ = 最低ダメージで確実に削れる範囲
  □ = 最大ダメージなら削れる範囲（運次第）
  ░ = 残りHP
  ■が100%超 = 確殺（最低ダメージでも倒せる）
  ■+□が100%超 = 運次第で倒せる可能性あり
```

**常にそのEnemyの現在HPを100%幅として割合表示する理由:** 絶対値のピクセル表示だと、数値が大きい場合にバーが画面外にはみ出す。割合表示なら数値の大小に関係なくバー幅が一定で、「倒せるか」の判断が常にバーの塗り具合だけでできる。

**コマンドセット後も常にプレビュー表示する理由:** ドラッグ中だけのプレビューでは、3人分の合計ダメージが把握しづらい。セット後も常時表示することで「全体通して何ダメージか」が一目でわかり、コマンドの入れ替え判断がしやすい。

### マウスオーバー情報

**キルラインバーにマウスオーバー:**
- バフ/レリック込みのダメージ内訳を表示
- 加算要素（Power+3等）→ 積み上げバーで可視化
- 乗算要素（×1.5等）→ 注釈テキスト
- 確率発動レリック等は将来的に検討

表示理由: バフやレリックの効果がどれだけダメージに寄与しているか見えないと、バフを使うモチベーションが湧かない。Ball x Pitのようにアイテムの寄与度が見えることで「このレリック強いな」「バフをかけた甲斐があった」が実感できる。

**武器/魔法アイコンにマウスオーバー:**
- 素のステータス（バフ/レリック抜き）: Power、ブレ幅、残り使用回数等

### 攻撃実行時の寄与度表示

```
戦士の攻撃！
  35ダメージ！
  └ 砥石 +15
  └ 精密 (確定)
```

ダメージ数字の下に控えめにバフ/レリックの寄与を表示。マウスオーバーしなくてもバフ/レリックの仕事ぶりが伝わる。

## ショップUI（ドラッグ&ドロップ方式）

### 設計方針

バトルUIとショップUIで操作体系を統一（ドラッグ&ドロップ）し、学習コストを最小化する。

**3人パーティーでショップ滞在時間が長くなる懸念への対策:** 「購入 → 誰に装備？」の2ステップを、ドラッグ&ドロップの1アクションに統合。さらに複数商品を同時にセットして一括確定できるため、1人ずつ買い物するよりテンポが良い。

### 画面構成

```
┌──────────────────────────────────────────────┐
│  ショップ                    所持金: 25G → 17G │ ← リアルタイム更新
├──────────────────────────────────────────────┤
│  武器/魔法                    [リロール 3G]    │
│  [鉄の剣 8G] [ファイア 6G] [大斧 10G] [アイス 7G]│
├──────────────────────────────────────────────┤
│  レリック              │  ポーション           │
│  [天使の天秤 12G] [砥石 8G] │  [HP薬 5G] [MP薬 5G]│
├──────────┬──────────┬──────────┬────────────┤
│  戦士     │  魔法使い │  僧侶    │ ポーション  │
│ ⚔短剣    │ 🔥ファイア│ ✚ヒール  │ 🧪[空き]   │
│ ⚔[空き]  │ 🔥[空き] │ 🙏[空き] │ 🧪[空き]   │
│ ⚔[空き]  │ ❄[空き]  │ ⚔[空き]  │────────────│
│ 👊パンチ  │ 🔮[空き] │ 🙏祈り   │ レリック    │
│          │ 👊魔力弾 │          │ 💎[空き]   │
│          │          │          │ 💎[空き]   │
├──────────┴──────────┴──────────┴────────────┤
│                  [確定] [店を出る]             │
└───────────────────────────────────────────────┘
```

**商品枠のカテゴリ分離理由:** 武器/魔法、レリック、ポーションはドロップ先が異なるため（武器/魔法→キャラ個別枠、レリック/ポーション→共有枠）、カテゴリごとに表示を分けることでドロップ先が直感的にわかる。

**ドラッグ時のグレーアウト:** 商品をドラッグした瞬間、ドロップできない場所（例: 武器を魔法使いの魔法枠に、レリックをキャラ個別枠に）はグレーアウトする。有効なドロップ先だけがハイライトされるため、試行錯誤なしに正しい場所に置ける。

**売却操作:** キャラ枠の装備を商品エリアにドラッグ&ドロップで売却。売却額が所持金に即反映される。入れ替え購入の場合も同様で、既存装備が商品エリアに戻り売却額が反映される。

### 操作フロー

1. 商品を**キャラの空き枠にドラッグ&ドロップ**
2. 所持金がリアルタイムで減る表示に変わる（プレビュー）
3. 入れ替えの場合、既存装備が商品エリアに戻る（売却額が所持金に反映）
4. **複数商品を同時にセット可能**
5. 「確定」で一括購入（所持金がマイナスなら確定ボタン無効）

将来的には武器/魔法屋とレリック/ポーション屋で分離も検討（選択の負荷軽減）。

### 価格バランス

- 3人分の装備を賄う必要があるため、価格を現行より低めに設定
- 戦闘報酬を現行より高めに設定
- 具体的な数値はプレイテストで調整

## 装備の所属

| カテゴリ | 所属 | 理由 |
|---------|------|------|
| 武器 | キャラ個別 | ビルドの個性が出る。装備することでそのキャラに発動する副作用（吸血の刃→HP回復等）が機能する |
| 魔法 | キャラ個別 | 同上 |
| レリック | パーティー共有 | パーティー全体に影響する効果が自然 |
| ポーション | パーティー共有 | フリーアクションで誰にでも使える設計と合致 |

**パーティー共有装備にしなかった理由:** 共有にするとキャラごとの「ビルド感」が薄れ、装備による副作用効果も実装しにくくなる。ショップのテンポ悪化はドラッグ&ドロップUIで解決できるため、個別装備のメリットを優先した。

## ダンジョン進行

### ステージ構成

- 7ステージ × 最終的に3階層
- 構成は現行維持（Stage 1-3: 通常、Stage 4: イベント、Stage 5-6: エリート混在、Stage 7: ボス）
- 敵のHP/攻撃力は3人パーティー前提で上方調整（具体値はプレイテストで調整）

### イベント（Stage 4）

```
休憩:     全員のHPをMaxHPの50%回復
宝箱:     共有レリック1個獲得
武器修理:  1人を選択 → その1人の全武器の使用回数を全回復
```

**武器修理を1人限定にした理由:** 「誰の武器を優先して修理するか」がリソース管理の判断になる。修理予定のキャラの武器を事前に使い切っておく、という先読み判断も生まれる。

### リソース管理（ダンジョン全体）

ダンジョン全体を通してのリソースマネジメントがこのゲームのコア:

```
管理対象リソース:
  - HP（キャラ個別）      → 休憩/ヒール/レベルアップで回復
  - MP（キャラ個別）      → ポーション/レベルアップで回復
  - 武器耐久（キャラ個別） → 修理イベント/レリックで回復。ダンジョン通して持ち越し
  - ゴールド（パーティー共有）→ 戦闘報酬+利息で獲得
  - ポーション（パーティー共有, 2枠）
  - レリック（パーティー共有, 5枠）
```

**武器耐久をバトル内リセットにしなかった理由:** ダンジョン全体のリソース管理がコアの遊びであり、武器耐久はその中心的な管理対象。バトル内リセットにすると「休憩所の前だから温存」「修理の前だから使い切る」等の先読み判断が消失する。

**プレイヤーに期待する判断例:**
- 休憩所の前 → 被弾が増えても武器を温存
- レベルアップ直前 → MP多めに使ってOK（50%回復が来る）
- 武器修理の前 → 修理予定のキャラの武器を使い切っておく
- 誰に止めを刺させるか → レベルアップのタイミング管理
- ポーションを誰に使うか → HP/MPの配分判断

### ゴールド・利息

- 基本システムは変更なし
- 3人分の装備を買う必要があるため戦闘報酬を高めに調整
- 具体的な数値はプレイテストで調整

## UI操作体系の統一

バトルでもショップでも「ドラッグ&ドロップで意図を表現し、結果がリアルタイムプレビューされる」で統一:

| 画面 | ドラッグ元 | ドロップ先 | プレビュー |
|------|----------|----------|----------|
| バトル | キャラの武器/魔法 | 敵 or 味方 | キルラインバー（常時更新） |
| バトル | ポーション | 味方 | 即時適用（フリーアクション） |
| バトル | 行動順スロット | スロット | 順序変更 |
| ショップ | 商品 | キャラ装備枠 | 所持金変化（リアルタイム） |

**統一した理由:** 操作の学習コストが低くなり、画面が変わっても同じ感覚で操作できる。
